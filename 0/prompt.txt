1. **Phase A — Parallel Read-Only Discovery Swarm (`dispatching-parallel-agents`):**
   - Dispatch `security-privacy-auditor`, `sqlite-temporal-architect`, and `bot-web-core-engineer` in parallel in **READ-ONLY mode** to analyze the impact of the requested feature or bug fix.
   - Each agent outputs a concise contract (schema changes needed, route/callback changes, and security edge cases) without modifying any files yet.

2. **Phase B — Strict File-Ownership Handoff Swarm (Zero Write Collisions):**
   - Execute code modifications through explicit sequential handoffs where each agent is only allowed to write to its owned files:
     - **Handoff 1 (`sqlite-temporal-architect`):** Exclusively edits `config.py` and `database.py` (schema, migrations, queries, Jalali/Tehran time logic).

     - **Handoff 3 (`security-privacy-auditor`):** Reviews the diff from Handoffs 1 & 2 for PII leaks, missing RBAC/ownership checks, CSRF, or upload vulnerabilities, applying surgical security patches if needed.
     - **Handoff 4 (`devops-vps-guardian`):** Updates `requirements.txt`, `.env.example`, Docker/systemd files, or CI workflows if dependencies or env vars changed.
     - **Handoff 5 (`tdd-qa-verifier`):** Exclusively edits `tests/test_*.py`, writes unit/integration tests for the new behavior, and runs `pytest -v`.

3. **Swarm Circuit Breaker (Self-Healing Rule):**
   - If `pytest -v` fails at Handoff 5, `tdd-qa-verifier` must NOT rewrite production logic itself; instead, it hands the exact traceback back to the responsible owner agent (`sqlite-temporal-architect` for DB errors, `bot-web-core-engineer` for handler/route errors) until 100% of tests pass.
